# K8s Console — 本地网关部署指南

> **目标**: 通过域名 `http://k8s-cicd.daiyi.local.com:9001` 访问本地 K8s 集群中的前后端应用。

---

## 二、链路层级速查

| 层级 | 组件 | 类型 | 地址 | 说明 |
|------|------|------|------|------|
| **L0** | 用户浏览器 | Windows 进程 | `k8s-cicd.daiyi.local.com:9001` | hosts 解析到 127.0.0.1，代理绕过 |
| **L1** | k8s-gateway | Docker 容器 | `0.0.0.0:9001 → :80` | nginx:latest，反向代理到 L2 |
| **L2** | ingress-nginx-controller | K8s DaemonSet + NodePort SVC | `:30000` (NodePort) | 集群流量入口，ingress-class: nginx |
| **L3** | k8s-console | K8s Ingress (prd) | host: `k8s-cicd.daiyi.local.com` | 路由分离: `/api` → backend, `/` → frontend |
| **L4** | k8s-console-backend | K8s ClusterIP SVC | `10.96.96.47:8000` | → Backend Pod (Django) |
| **L4** | k8s-console-frontend | K8s ClusterIP SVC | `10.96.230.7:80` | → Frontend Pod (Vue SPA) |
| **L5a** | Backend Pod | K8s Deployment (1/1) | Django + Gunicorn :8000 | 连接 MySQL (3306) + Redis (6379) |
| **L5b** | Frontend Pod | K8s Deployment (1/1) | nginx :80 静态文件 | Vue SPA try_files 路由 + Gzip |

## 五、部署与启动

### 5.1 构建镜像（首次 / 代码变更后）

```bash
# Backend（多阶段构建，无需预装依赖）
DOCKER_BUILDKIT=0 docker build --pull=false -t k8s-console-backend:latest -f backend/Dockerfile backend/

# Frontend（先编译 Vue，再打包 nginx 镜像）
cd frontend && npm run build && cd ..
DOCKER_BUILDKIT=0 docker build --pull=false -t k8s-console-frontend:latest -f frontend/Dockerfile.local frontend/
```

> `DOCKER_BUILDKIT=0 --pull=false` 解决 Docker Hub 不可达时的构建问题。

### 5.2 部署 K8s 资源

```bash
kubectl apply -f deploy/console/
```

部署顺序无关紧要（K8s 自动按依赖处理），全部创建在 `prd` namespace。

验证：

```bash
kubectl get pods -n prd
# 预期: k8s-console-backend-xxx  1/1 Running
#       k8s-console-frontend-xxx  1/1 Running

kubectl get ingress -n prd
# 预期: ADDRESS 不为空
```

### 5.3 配置 Windows hosts

管理员权限编辑 `C:\Windows\System32\drivers\etc\hosts`：

```
127.0.0.1 k8s-cicd.daiyi.local.com
```

### 5.4 配置 Windows 代理绕过 ⚠️ 关键

如果 Windows 开启了系统代理（常见于 VPN/代理工具），Chrome 会把所有请求先发给代理，代理不理解自定义域名 → 返回 502。

```bash
# 1. 检查是否开启了代理
reg query "HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Internet Settings" //v ProxyEnable
reg query "HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Internet Settings" //v ProxyServer

# 2. 追加自定义域名到绕过列表
reg add "HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Internet Settings" //v ProxyOverride //t REG_SZ //d "原有值;*.daiyi.local.com" //f
```

或 GUI：设置 → 网络和 Internet → 代理 → 手动编辑请勿代理列表。

**配置后重启 Chrome。**

### 5.5 启动本地网关

```bash
bash deploy/gateway/start.sh
```

脚本自动：检查 NodePort → 拉取镜像 → 停止旧容器 → 启动新容器 → 验证 3 个端点。

### 5.6 验证

```bash
# 3 个健康端点
curl http://localhost:9001/ -H 'Host: k8s-cicd.daiyi.local.com'         # 前端页面
curl http://localhost:9001/api/health -H 'Host: k8s-cicd.daiyi.local.com'  # 后端
curl http://localhost:9001/gateway-health                                    # 网关自身

# 通过域名直达（需要代理绕过配置正确）
curl http://k8s-cicd.daiyi.local.com:9001/
```

浏览器访问：**http://k8s-cicd.daiyi.local.com:9001**

### 5.7 停止

```bash
bash deploy/gateway/stop.sh
```

## 六、故障排查

### F1: Pod `ImagePullBackOff`

镜像未构建或不在 registry 中。需要本地构建（见 5.1）。

```bash
# 检查镜像是否存在
docker images | grep k8s-console
```

### F2: 浏览器 502 — WSL wslrelay.exe 端口冲突（80 端口专属）

**现象**：curl 正常，浏览器 502。Docker 日志中看不到浏览器请求。

**根因**：WSL 的 `wslrelay.exe` 占用 IPv6 回环 `[::1]:80`，浏览器 IPv6 localhost 请求被拦截。

**解决**：本项目已改用 **9001 端口**规避。

**诊断**：`netstat -ano | findstr ':80.*LISTENING'` → PID 9612 = wslrelay.exe

### F3: 浏览器 502 — Windows 系统代理拦截

**现象**：
- `curl --noproxy '*' http://k8s-cicd.daiyi.local.com:9001/` → ✅ 200
- `curl --proxy 127.0.0.1:9674 http://k8s-cicd.daiyi.local.com:9001/` → ❌ 502
- Chrome 浏览器访问 → 502

**根因**：系统代理不理解 `k8s-cicd.daiyi.local.com` 域名。

**解决**：见 5.4 配置代理绕过，重启 Chrome。

### F4: Git Bash 路径翻译错误

**现象**：容器报错 `no such file or directory`。

**根因**：Git Bash (MSYS2) 把 `/etc/nginx/...` 翻译成 `C:\Program Files\Git\etc\nginx\...` Windows 路径。

**解决**：`start.sh` 已内置 `MSYS_NO_PATHCONV=1` + `$(pwd -W)`。

### F5: K8s Ingress 不生效

**检查链路**：

```bash
# 1. Ingress 状态（ADDRESS 不为空 = 正常）
kubectl get ingress -n prd

# 2. ingress-nginx 是否运行
kubectl get pods -n ingress-nginx
kubectl get svc -n ingress-nginx

# 3. 绕过所有代理，直连 NodePort 测试
curl --noproxy '*' http://localhost:30000/ -H 'Host: k8s-cicd.daiyi.local.com'
```

### F6: 后端连不上 MySQL / Redis

```bash
# 检查后端日志
kubectl logs -n prd -l app=k8s-console-backend --tail 50

# 检查 ConfigMap 和 Secret
kubectl get configmap -n prd k8s-console-config -o yaml
kubectl get secret -n prd k8s-console-secret -o yaml

# 确认数据库 Service 在 database namespace 运行
kubectl get svc -n database
```

## 七、设计决策

| 决策 | 原因 |
|------|------|
| 镜像 `nginx:latest` 而非 `openresty/openresty:jammy` | 更小、更快、功能足够 |
| 宿主端口 `9001` 而非 `80` | 避免 WSL wslrelay / IIS 抢 80 端口 |
| NodePort (30000) 而非 `kubectl port-forward` | NodePort 随集群存活，不依赖终端 |
| `host.docker.internal` 解析宿主机 | Docker Desktop 内置，无需 `--add-host` |
| Backend `imagePullPolicy: Always` | 开发期镜像频繁更新，确保拉取最新 |
| Frontend `imagePullPolicy: IfNotPresent` | 静态文件变更少，减少拉取 |
| `Dockerfile.local` vs `Dockerfile` | `.local` 手动构建（先 `npm run build`），CI 版多阶段构建 |
